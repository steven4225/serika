# QQ 群模式：NapCat / OneBot v11

## 已确认的行为

- 一个指定群、一条共享 Thread、独立群工作区。不同成员可以接着群助手的上文提问；所有回复、工具参数及结果在群内可见。
- 只接收指定机器人账号、指定群、五分钟内的新消息；必须包含真正的 `@机器人` 消息段。第一版只处理文字，不下载图片、文件或转发记录，不把 CQ 字符串当作控制指令。
- 所有成员均可提问。文件、Shell 和网页工具须由配置的主人逐次批准；群管理员身份、昵称、聊天内容均不授予权限。工具默认关闭，示例仅启用工作区文件工具。
- Memory、checkpoint、个人 Todoist、安排/定时任务、Computer、Skills 和自动整理不接入 QQ 模式；不读取桌面的配置和对话。共享 Thread 保存已完成聊天记录，重启后仍可接着聊。
- 使用现有 Controller / AgentLoop 和本地执行回执，不另建模型循环。QQ 来源不继承桌面或 Telegram 授权。忙时说明未排队；普通消息不是 Steer。

Before：目前不能通过普通 QQ 号在群内使用 Serika 的问答和受主人审批的工具。

After：NapCat 账号进群后，成员 `@机器人` 提问，主人批准一次工具操作，结果回到同一个群。

## 配置与启动

前提：Node >= 22.12、仓库依赖已安装；NapCat 已安装并登录专用 QQ 号，该账号已经进群。安装和登录 QQ 由用户完成，本功能不安装 NapCat 或接管个人 QQ。

1. 在 NapCat 的网络配置中启用 **WebSocket 服务端（正向 WS）**，建议只监听 `127.0.0.1:3001`，配置非空 Token，消息上报格式选 **array**。此 Token 是 OneBot 的网络 Token，不是 NapCat WebUI 登录 Token。连接根路径 `/`，同时承载事件和 API；不要填 `/api`、`/event` 或反向 WS 地址。
2. 新建一个专用群工作区，将 `apps/desktop/config/qq.example.json` 复制到该工作区和仓库以外，例如 `~/.config/serika/qq.json`。填写 `botId`、`groupId`、`ownerId` 和绝对 `workspace`。这些 ID 均为数值，群主和助手主人可以是不同的人。
3. 将 `apps/desktop/config/qq.env.example` 复制到同一外部目录的 `qq.env`，填写绝对 `QQ_CONFIG`、`QQ_ACCESS_TOKEN` 和独立的模型配置；不要复制整份个人桌面环境文件。环境文件权限设为 `600`，配置不得被其他用户修改。
4. 在仓库根目录运行：

   ```sh
   pnpm build:runtime
   pnpm --filter @aisdk-agent/desktop exec tsx --env-file="$HOME/.config/serika/qq.env" src/main/qq-entry.ts
   ```

   若所需变量已由可信环境提供，可直接运行 `pnpm qq`。该命令构建 Runtime 后启动 QQ 模式，不自动读取仓库 `.env`。成功时终端显示已连接的群、机器人和主人账号。

本地 WS 仅接受 loopback；跨机器须使用显式配置的可信 `wss://`，且由使用者配置 TLS 和网络。Token 通过 Authorization 请求头发送，不放进 URL。

关闭 QQ 模式用终端 `Ctrl+C`。它是独立前台进程，关闭 Electron 不会停止它，关闭该进程则停止接收；本版不自动安装常驻服务。配置改变后须重启。更改同一配置的群、账号、主人或工作区会因旧绑定不匹配而拒绝启动，应使用另一份外部配置建立新实例，不可清空旧证据来改绑。

## 群内操作

以下每条都须 `@机器人`：

| 操作 | 谁能发送 | 行为 |
| --- | --- | --- |
| 普通文字问题 | 群内成员 | 空闲时开始一轮共享对话；忙时未排队 |
| `允许 ABCDEF1234` / `拒绝 ABCDEF1234` | 仅配置的主人 | 处理当前一次工具确认 |
| `当前确认` | 仅主人 | 为同一待确认工具换一个新短码，旧码立即失效 |
| `停止` | 仅主人 | 请求取消；已执行的操作不会撤回 |
| `状态` | 群内成员 | 查看忙闲、容量、待核对入站消息 ID 和未知投递数量 |
| `结果 <消息ID>` | 群内成员 | 显式读取已保存执行回执的结果预览；不启动模型或重做工具 |
| `核对 <消息ID> <实际观察>` | 仅主人，空闲时 | 记录人工观察、解除该未知入站的接单阻塞；保留原未知状态，不重做旧请求 |

短码五分钟有效，绑定完整工具参数、Tool Action、Run、当前来源和固定群绑定；单次消费，重启后不恢复。参数太长不能完整展示时不提供批准码，主人应停止本轮并缩小操作。多条工具调用分别确认。消息结构化发送，模型回复中的 `[CQ:...]` 保持普通文字。

## 五分钟用户 Demo

前提：以上配置完成，已连接；示例中的文件工具开启；准备一个从未使用过的文件名 `qq-demo-<唯一后缀>.txt`，助手空闲。

1. 普通成员 `@机器人`：“只用 write_file 创建上述文件，内容为 QQ demo，不做其他事。”
2. 机器人在群内发出完整工具参数和确认码。此时群工作区没有该文件。
3. 让另一成员 `@机器人` 发送该允许码：应提示仅主人可批准，文件仍不存在。
4. 主人 `@机器人` 发送该允许码：文件出现，内容为 `QQ demo`，群里收到本轮结果；对应回执有一次成功的 `write_file`。
5. 再发同一码：应提示无效或已处理，回执没有第二次写入。另一成员询问刚才的文件内容，机器人能看到群内上文；若需读取文件，仍要主人批准。

失败条件包括：其他成员能批准、未批准就出现文件、重复码导致第二次写入，或结果发到别的群。是否真实执行以文件和执行回执为准，不以模型“已完成”的表述代替。

## 恢复与存储边界

- 外部配置旁的 `.serika-qq-<配置路径摘要>/` 保存固定绑定、入站去重/关联、投递状态、运行配置快照、transcript 和执行回执。不保存网络 Token。配置及群工作区的双重 flock 防止同一配置或复制配置在同一群工作区重复运行；不要在不同机器或不同工作区同时接入同一机器人和群。
- 每条入站先持久化；Run 在创建屏障绑定来源后才能执行。调用发送前保存投递意图，成功回执只代表 NapCat 返回消息 ID，不代表成员已读。
- 请求超时、断线或发送后回执缺失均可能为未知，不自动重发消息或工具。NapCat 断线时请求取消当前执行，需要核对后重新启动，不自动重连。
- 重启将未完成入站和发送标为未知，不恢复批准码或重放执行；主人用 `状态` 获取待核对 ID，再检查对应 transcript/执行回执和实际产物，最后提交人工观察。未知投递可以通过新的 `结果 <消息ID>` 请求显式查看结果预览，旧投递仍保留未知。
- 活动日志最多 4096 条入站和 4096 条分段投递，文件最多 8 MiB；达到上限或保存不明时停止接收，保留既有证据。本版没有自动归档或无限容量承诺。
- 群工作区不接入个人记忆，但本机 Shell（若显式启用）仍拥有宿主进程权限；工作区路径不是 OS 沙箱。主人须核对工具完整参数后批准。
