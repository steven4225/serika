# 实际能力查询与命令配方

本功能不安装插件、不修改安全配置、不启动 CUA 服务，也不将外部 text Skill 升级为可执行脚本。继续使用原来的 AgentLoop、工具审批和 Shell 执行器。

## 看清当前能力

桌面能力页展示当前注册的工具；桌面命令 `/capabilities`、绑定 TG 私聊中的 `/capabilities`、模型的 `capability_status` 都来自同一份运行时清单，不扫描其他应用的工具目录，不读取凭证，不发模型请求。

“已配置”“已注册”不等于服务可连接或系统权限已授予。CUA 启用时，可以让助手调用 `computer_check`，经本次批准后检查配置的驱动可执行性与 `list_apps` 连接，只返回允许列表中的运行应用，不读窗口、截图或内容。请求失败不能确定原因时保留未核实，不猜成缺辅助功能权限；观察某个允许应用仍需另行批准 `computer_observe`。不会自动安装、启动驱动或弹系统授权。

## 一个可验证的五分钟示例

前提：在指定的非敏感测试工作区启用 Shell；若需要生成脚本，另启用文件工具。使用真实模型可能产生现有服务的调用费用，代码测试不会自动调用付费 API。

1. 在桌面或已绑定 TG 交办：“检查这个项目的改动，生成 summary.md，检查内容；做成以后可复用的命令配方。”
2. 助手用现有工具完成检查和产物；在最终改动之后执行一次检查命令。程序保存它的真实 Shell 回执。
3. 助手请求登记配方。预览中核对完整命令和相对目录，再批准。`recipe_save` 只能登记当前主 Run 中确实以 0 退出、未超时/取消的同一命令，不能用自述、旧 Run、截断回执或不同命令冒充测试。之后又派发文件修改、Shell 或电脑写操作会使旧测试失效。
4. `/recipes` 查看；换新对话或正常退出重开后，请它复用该配方。`recipe_run` 必须提供当前 hash，展示具体命令，再批准这一次执行。检查本次新产物，不能用旧成功回执替代。
5. 要求停用，批准 `recipe_manage` 后再次运行应被拒绝。更新会保留已测试命令版本，可选择旧 hash 回退；回退不会自动执行命令、撤销已经发生的效果或恢复任何授权。

## 授权与版本边界

- 配方是有明确参数的**命令文本版本**，不是可获得权限的 Skill，也不是新工具安装器。当前只支持固定 command/cwd，不插入模型生成的动态参数。
- 一次批准可运行该命令里的完整步骤，不为每个子命令重复确认；新的工具和其他命令仍按既有权限批准。主机 Shell 不是沙箱。需要严格限制文件与网络时沿用显式 Docker 沙箱，不会把 workspace 路径或命令关键词当隔离保证。
- 原 `/authorize` 的文件范围与 Docker 专用 `/authorize-shell` 仍是下一次 Run 有效；配方登记和应用重开都不恢复它们。没有给主机 Shell 增加默认免确认。
- hash 固定 id、描述、command、cwd；**不冻结命令引用的外部脚本、依赖、Git 状态或其他文件**。优先用自包含命令。外部脚本变化后应重新检查并登记；不能将命令版本说成整个环境版本。
- 退出码 0 证明命令确实成功退出，不证明测试充分、业务正确或未来一定成功。产物内容仍需核查。
- 成功、失败、取消、超时和未知效果继续走原执行回执。未知效果不自动重放；发送失败不重新执行配方。

## 存储与范围

配方存于当前 workspace 的 `.runloom/recipes.json`，最多 32 个配方，每个最多 8 个已测试版本，总文件不超过 64 KiB；命令不超过 1 KiB。版本满时拒绝新写入，不静默删历史。锁、revision CAS、临时文件同步和原子替换保护目录，损坏/符号链接不覆盖；替换后的确认失败按效果未知处理。

仅启用 Shell 的交互主助手注册配方工具。worker、记忆整理、无工具 Skill 不因此获得 Shell，也不自动排期执行配方。本轮构建和脚本模型验收不证明日用 Electron 已重载、真实 TG 已操作或任意脚本依赖已封闭。
