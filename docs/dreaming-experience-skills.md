# Dreaming → 可复用经验方法

## 用户结果

- Before：助手完成并验收过类似任务，但新对话仍需要重新解释同一套方法。
- After：显式启用经验学习后，应用在空闲时从已验收 WorkTask 提炼文本方法；新对话按相关性选用，用户能查看来源、停用和恢复。
- Demo（五分钟，前提已有两条合格经验）：桌面工作区 → 自动安排下的「经验学习」→ 开启；等沉淀完成或点「沉淀经验」→ 展开来源 → 新建对话、给另一项目的复盘材料 → 查看「最近一轮选用的方法」→ 停用 → 再建对话问同类任务，选用清单应为空。没有合格经验、坏文件、整理失败不是同一个空状态。

## 一条闭环，不增加行为循环

```text
显式验收的 WorkTask + 最新归属正确的 primary 回执
    → 程序筛选最多 8 条 / 12 KiB
    → 现有 AgentLoop 的无工具、单步反思 Run
    → 严格 JSON + 再核对来源 / 记忆版本
    → 原子保存方法、版本、处理收据、选用来源快照
    → 新 primary Run 选择最多 2 条 / 指令合计 4 KiB
```

反思 Run 使用工作区绑定的维护 Thread，输入不会进入正常对话历史或事实记忆整理。维护执行同时占工作区 WorkTask 租约和 transcript 执行租约；不同 transcript 目录也不能同时反思同一工作区。普通聊天抢占后台反思并等待实际结算。没有独立常驻服务、外部数据库、额外 API 或模型训练。

## 开启与输入

可信配置必须位于 workspace 外；默认关闭。桌面只在用户点击后写配置并重新加载，不自动修改日用配置。

```json
{
  "automation": {
    "dreaming": { "enabled": true }
  }
}
```

每批至少两条新的独立经验。只读当前 workspace 的最多 100 条 completed WorkTask；每条必须具有：

- 最新关联、归属正确、已完成的 primary Run，不含 unknown/started/requested 工具效果；
- 无 unresolved 的交付，所有 required 条件通过；
- 至少一个 required 人工质量项通过，且能对上保存的 human evidence；
- 可核对的当前记忆依赖。第一版方法是 workspace 级，不沉淀依赖 Thread 私有记忆的经验。

模型只收到目标、有限交付/回复预览、人工反馈、工具身份与状态、文件/测试结构化回执和记忆版本，不读取全部私人 transcript，不读取任意文件。截断会明确标记，摘要和模型成功声明不能冒充程序事实。

旧回执没有 memoryReferences 时只能按空依赖兼容，不能声称旧记忆引用已完整追溯。新 Controller 保存本轮实际准备过的记忆版本；覆盖超过 16 条时不学习该经验。

## 存储、失败与停用

`.runloom/dreaming.json` 是 host 管理的派生方法数据，**不是**被信任的外部 Skill 包，不作为 SKILL.md / 脚本自动加载。事实记忆仍在原 memory.json 中。

- 最多 32 个方法、每条 8 个历史正文版本、512 个来源快照、整个文件 1 MiB；满了报错，不静默删除来源。
- 临时文件 fsync → rename → 目录 fsync，写入受 flock 保护。方法、已处理经验收据和模型实际选用的来源快照同一笔提交。
- JSON 非法、引用伪造、来源改变、取消：不推进处理收据。相同批次回放返回原收据，不重复写方法。
- rename 后确认失败为 uncertain：可能已经保存，必须刷新核对，不能说“没写入”或用取消掩盖。
- 新内容更新保留停用状态；恢复生成新 revision，不恢复工具授权。启停均使用 revision CAS。
- 启停不重复耗用相同正文的历史槽位；历史满仍可停用，不删除旧版本。正文更新与恢复在容量满时拒绝。
- v2 文件保存有界任务与执行回执快照，不复制完整对话或任意磁盘文件。来源回执被 journal 正常裁剪后，可用快照核对；当前任务仍必须存在且内容一致。任务撤回或改变、当前记忆依赖失效，方法仍不选用。
- 如果 journal 中仍有来源 Run，必须以它核对，不能用归档掩盖改变、未知效果或损坏。读取损坏仍报错，不当作正常裁剪。
- v1 只读兼容，不会读取时改写。下一次实际写入升级到 v2；显式启用或恢复旧方法时可归档仍存在的合法来源，不能凭空补回已经丢失的旧证据。
- 每次选用重新核对来源、记忆版本、启用状态、时间和范围。归档是可追溯的派生依据，不是当前文件事实，也不授予工具权限。

选用只是准备上下文的证据，不证明 provider 收到、不证明模型遵循、更不证明当前任务已成功。当前用户指令优先；任何文件、Shell、应用控制调用仍走原权限确认。

## 验证入口

离线默认测试覆盖真实 JSONL、任务/回执存储、flock、Controller 和 AgentLoop；模型是脚本。含生成、换 Thread、运行时重开、停用、恢复、前台抢占、坏 JSON 和 uncertain 故障。归档测试用生产 journal 的 50 条保留策略裁剪来源后重建运行时，验证再次选用，不重放旧任务。

```sh
pnpm typecheck
pnpm test
```

真实配置模型链显式开启，不属于默认付费测试：

```sh
RUNLOOM_DREAMING_ACCEPTANCE=1 node --env-file=.env --test \
  --test-name-pattern='real configured model' \
  examples/cli/dist/dreaming-acceptance.test.js
```

用隔离 fixture 验收，拒绝 mock fallback。来源夹具的人工接受不代表生产内容质量。运行时重开与原生 Electron 人工点击、完整进程重启是不同证据；报告不能拼成已经全部封板。
