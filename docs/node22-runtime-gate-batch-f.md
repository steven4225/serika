## Before

先前报告的 Node 22 单文件测试是 53 项中 14 通过、39 取消。`AbortSignal.timeout` 的计时器不保持进程存活，挂起调用可能在超时处理前失去事件循环工作。main 已通过 `invocationDeadline` 修正此问题，但 CI 只有整套测试命令，未把原单文件复现命令列为独立门禁。

## After

现有 `packages/ai-sdk-adapter/src/loop.ts` 为每次模型、工具调用创建保持进程存活的截止时间计时器，在结算时清理。工具确认仍在工具截止时间之外；未知副作用仍停止并等待核对。这些生产机制已存在，本批不再次改写。

最低版本 CI 先用支持 pnpm 11 的工具链构建，再切换到 `22.12.0`，直接运行原单文件命令；随后原有全套 Runtime、桌面与脚本门禁继续运行。不升级声明的运行下限、不删测试、不通过重试掩盖失败。

## 五分钟 Demo

前提：依赖已安装；本地可用 Node 22.12.0（pnpm 11 的安装／构建需要 >=22.13 的受支持工具链）。

1. 仓库根目录用现有工具链运行 `pnpm build:runtime`。
2. 用 Node 22.12.0 的可执行文件检查 `--version`，应是 `v22.12.0`。
3. 用同一个可执行文件运行：

   ```sh
   node --test packages/ai-sdk-adapter/dist/loop.test.js
   ```

4. 应完整结束：53 项通过、0 失败、0 取消，退出码 0。挂起模型／工具的超时及确认等待仍受原断言检查。
5. 在 PR 的 `runtime-minimum` 检查中核对新增单文件步骤，再核对后续完整测试步骤均通过。

模型请求错误日志是错误分类测试的夹具输出，不是调用真实提供商。本 Demo 不证明真实模型、手机或日用 Electron 链路。
