# Serika Desktop

Electron 前端通过 `createRuntimeApp` + `createAssistantController` 接入后端，不创建第二条 AgentLoop。

## 能力开关与对话容量

Before：模块能力是只读清单，关闭能力需要手改配置；压缩页默认铺开内部参数，无法判断是否需要操作。

After：模块能力页可预览并保存开关，空闲时重新装配同一个 Thread，历史与草稿保留。已有声明只更改 enabled；尚未声明的基础模块使用后端默认参数，不安装凭据、不授予工具权限、不自动替换后台服务。Todoist 缺凭据会明确报错；本机控制必须先配置驱动和允许的应用，不能自动授权。启用失败恢复原配置；配置被其他程序修改时拒绝覆盖。自定义 Skill/Hook 的依赖冲突会报错，不静默删规则。所有进程内模块重建，正在走的番茄钟会结束。关闭 task 不取消已保存安排或停止独立 worker。

上下文页先解释自动管理状态和上次发送前的准备结果；没有估算就不显示 0 或虚构进度。历史摘要与这轮准备分开，失败仍显式显示。手动整理与技术参数默认折叠；整理后区分新摘要、无需新摘要和失败，原始对话不删除。

五分钟 Demo：打开模块能力，关闭番茄钟并保存，回到番茄钟确认不可用；完整退出重开，确认仍关闭；重新开启后可操作。打开上下文与压缩，不展开技术详情即可看懂自动管理状态；展开「需要提前整理？」并点「现在整理」，核对实际结果。没有旧内容时应显示无需新摘要，不能冒充生成成功。

## 启动与验证

日用入口（自动构建两仓，读取后端现有受信任 `.env`；优先使用已配置模型，未指定时优先 Command Code，再 DeepSeek；没有真实模型凭据时报错）：

```sh
cd /Users/a1-6/Code/agents/runloom-desktop
pnpm daily
```

默认配置、会话列表和 transcript 在 Electron userData 中持续保存。首次没有 `RUNLOOM_WORKSPACE` 时创建 `userData/workspaces/personal`；测试窗口应使用独立 userData 并设置 `RUNLOOM_DESKTOP_TEST=1`，页面会显示隔离验收标记。`pnpm dev` 仍是开发入口。已有进程要从托盘完整退出后再启动，关闭窗口只是隐藏。

macOS 的 `pnpm daily` 使用本仓库 `dist/local-<Electron版本>/Serika.app`，而不是直接运行依赖里的 `Electron.app`。首次生成会复制 Electron 运行时、设置原生名称/图标并做本机 ad-hoc 签名；后续启动复用它，实际代码仍加载本仓库最新的 `out/`。Finder 也可双击该应用启动（默认读取后端 `.env`，特殊模型/配置覆盖仍用 `pnpm daily`）。这是依赖当前 checkout 的本机入口，不是独立安装包，不能复制给别人使用。`pnpm dev` / `pnpm preview` 仍使用 Electron 开发宿主，系统名称可能显示 Electron。日用默认 profile 始终是 `~/Library/Application Support/@aisdk-agent/desktop`，改品牌不迁移或清空旧历史；显式 `RUNLOOM_USER_DATA` 仍优先。

原生名称补正验证：`pnpm run check` 通过（187 项桌面测试 + 2 项启动环境测试）；生成的本机 bundle 通过 `codesign --verify --deep --strict`。隔离副本使用独立 userData/workspace，通过 Cua 的新鲜原生窗口状态核对 `app_name`、窗口标题、应用菜单均为 Serika，界面显示隔离标记。没有打开日用历史或发送模型请求；日用旧历史保留由固定路径和相关测试覆盖，不冒称已做日用数据验收。

先构建链接的后端，再启动桌面：

```sh
cd /Users/a1-6/Code/agents/aisdk-agent-framework
pnpm build
cd /Users/a1-6/Code/agents/runloom-desktop
pnpm check
pnpm dev
```

使用真实模型与外部配置（配置不能放 workspace 内）：

```sh
cd /Users/a1-6/Code/agents/runloom-desktop
RUNLOOM_MODEL=deepseek RUNLOOM_CONFIG=/absolute/path/runloom.json \
  node --env-file=../aisdk-agent-framework/.env node_modules/electron-vite/bin/electron-vite.js dev
```

不指定身份时，Electron userData 下的 `desktop-identity.json` v2 按 config/workspace 保存当前 Thread 与最多 100 个对话入口；旧 v1 身份读取时保留，实际登记/切换才迁移。切到另一份配置/workspace 再回来仍能接回之前选择的 Thread。坏身份文件会报错，不会自动清空。第二份桌面进程只聚焦第一份窗口。

侧栏「历史对话」可查看、创建、切换当前工作区的 Thread；切换要求 Controller 空闲，释放旧租约并装配同一套 Controller，所有旧预览/输入清空。旧目录先只读发现，再由用户确认所选对话属于当前工作区并登记；不复制、不合并 transcript，不把未登记的其他目录当成本工作区历史。列表发现不调用 Store 的截尾修复，不写 JSONL；坏/超限/未完整结束的历史明确报错，不能显示为空。

`RUNLOOM_THREAD` / `RUNLOOM_TRANSCRIPTS` 可显式覆盖，不改写默认身份；部分覆盖从匹配身份补齐，无匹配时用稳定隔离默认值。以相同覆盖重启才能回到同一对话。`RUNLOOM_WORKSPACE` 只在首次生成配置时生效，已有配置以文件实际 workspace 为准。

新生成的 `runloom.json` 默认开启记忆、自动整理、`writePolicy: "automatic"`、一次有界同义查询改写和模型摘要压缩。只有符合自动写入策略、来源核对及冲突规则的提案才自动保存，其余候选留待处理；`writePolicy: "review"` 则要求人工接受后才成为正式记忆。压缩使用固定的 32K 窗口、4K 输出预留、1K 安全余量、8K 近期保留、4K 摘要输出。已有配置的记忆开关/预算不自动修改；记忆页的「设置日用记忆」先展示配置预览，确认后校验配置并重建当前会话。坏配置不会覆盖成默认值。

记忆页区分未启用、等待整理、整理中、整理失败、没有新增候选、等待审核；失败可重试增量整理，不推进游标。首次最多取最近八条符合条件的用户消息，更早内容从「选择历史消息补整理」明确选择 1–8 条，使用原文核对、不截断所选消息、不移动自动游标。标记排除的消息、合成整理请求和自动路径的记忆工具回合不取材。最近尝试/跳过说明属于当前进程，重开后不把旧进程报告当新一次结果。相同的 pending 变更只审核一次；更宽泛的语义去重由模型提出且仍需审核，不能据此保证所有同义内容都去重。整理每步 30 秒，总时限 120 秒，仍是单路串行 followup。

没有选择真实模型时，默认 mock 仍可用于界面调试，但主屏会显示明确警告，不把它当真实任务能力。日用启动请显式指定模型，复用受信任的环境文件（不显示或复制 Key）：

```sh
cd /Users/a1-6/Code/agents/runloom-desktop
RUNLOOM_MODEL=command-code \
RUNLOOM_ENV_FILE=/Users/a1-6/Code/agents/aisdk-agent-framework/.env pnpm dev
```

模型配置不会在运行中切换；修改后完整退出桌面并重新启动。

### 执行中补充要求（Steer）

前台用户任务运行中（包括等待工具确认），输入框可发送「补充要求」。它进入同一个 Run，不启动新任务；正在执行的工具不会被撤销，未派发的旧操作会停止，旧确认会失效，新调用仍需重新确认。工作任务的目标和验收条件不会因此被修改。整理、手动 Skill 和后台任务不接受 Steer。

界面按实际凭证显示「已接收，等待当前步骤结束」「已加入后续规划」或「本轮未应用」。加入规划不证明模型已遵从，也不证明工具已执行。本条默认不整理为长期记忆。运行已结束、预算不足等未应用内容可显式移回草稿，不自动重发。

若 IPC 接收结果未知，草稿保留且重复发送被阻止，先点击「核对接收状态」。执行记录保存补充状态；刷新或重启不会把历史补充自动提交。完整 Demo：让它修改隔离测试文件，等写入确认 → 发「保留全文，只在末尾追加两条行动」→ 旧确认消失，新调用重新确认 → 核对读回回执与文件，并确认 Run ID 未变。此 Demo 需真实模型和已开启的文件工具，不在日用文件上测试。

## Command Code 与指定应用控制

桌面支持 `RUNLOOM_MODEL=command-code`，复用后端模型入口。可通过主进程显式加载受信任的环境文件；已有进程环境变量优先，不隐式寻找 cwd 下的 `.env`，不把 Key 发往页面或 IPC：

```sh
RUNLOOM_ENV_FILE=/Users/a1-6/Code/agents/aisdk-agent-framework/.env \
RUNLOOM_CONFIG=/absolute/outside-workspace/runloom.json pnpm dev
```

环境文件含 `RUNLOOM_MODEL=command-code` 与 `COMMAND_CODE_API_KEY`。缺凭据、坏文件或配置错误会显示启动失败，不静默回退模型。Computer 配置沿用外部 `modules.computer` 的 enabled/executable/allowedBundleIds；仅显示已配置，不承诺驱动可用，不自动安装、启动 daemon 或申请权限。本机 Cua Driver 不需要模型 Key。

Computer 确认卡显示精确 bundle/PID/window、动作和完整输入，技术 token 可展开；按 approvalId 提交一次确认，过期不重试、不批准新调用。空 preview 时不会绕过确认。原始 UI 文本只按纯文本展示。

`confirmed` 仍显示已派发、效果待核对；`suspected_noop` 不能被自动重试。实时事件、刷新快照和最终回执共用展示规则，`outcomeUnknown`/unknown 优先显示人工核对。主 Run 结束或取消后重读 getRun，不能仅凭 cancelled 认定没有副作用。Run completed 只表示本轮结束，不代表任务验收。

面板读取 `getContextDiagnostics()`，展示实际配置、估算器、最近合法压缩记录和本进程最后一次上下文准备。查询不调用模型、不创建 Run、不写 JSONL。历史记录通过 transcript 前缀校验，不等于当前 Run 已使用它；重启后本进程准备结果为空。读取失败保留上次数据并标明过时，缺失 usage 不显示成零。

手动压缩仍是空闲 `/compact`；忙时按钮禁用。估算输入不是 provider 的精确 tokenizer 计数。摘要不是长期记忆、磁盘事实或工具授权。关闭模型摘要仍有既有历史裁剪。

1. 在普通对话输入「我的长期写作偏好：我写复盘时先给一句结论，再列两条行动。这一轮只回复收到，不要调用工具。」不勾「本条不整理为记忆」。等主回复和整理都结束。
2. 点击候选的「完整审核」，核对原话及拟保存内容，范围应为当前工作区；点击「保存这条记忆」。候选退出待审列表，保存回执出现；点击「查看已保存」核对正文。「审核记录」保存来源对话的接受/拒绝/失效记录，不是正式记忆的版本历史。
3. 从应用退出菜单或托盘「退出 Runloom」彻底退出（关闭窗口只隐藏）。用同一入口重开。旧对话的消息应仍在，侧栏最近对话可打开它；「查看全部对话」保留显式登记旧目录的入口，不自动扫描别的工作区。
4. 点击「新对话」，输入「写复盘时，我习惯先写什么？之后列几项？请依据已保存的长期记忆回答，并给出记忆 ID。不要调用工具。」核对回答是一句结论、两条行动；展开「本轮参考记忆」，应选中同一条已保存的内容与 ID。
5. 查阅后点「回到对话」，应回到原滚动位置；不会自动抢输入焦点。窄窗口保留「查看全部对话」图标，完整记录在同一窗口展开。

保存回执只证明保存完成；「本轮参考记忆」是后端上下文准备选中的版本，不是模型自报，也不保证模型遵循。其他 Thread 看不到原候选，workspace 正式记忆仍可按问题匹配使用。修改、停用、撤回及历史恢复沿用已有的显式预览/版本校验，不恢复工具授权。整理状态折叠说明，读取失败与失败重试仍明确可见。
